# Test Scenarios — Humstrava

## ESP32

### E-01 — Нормальная отправка
**Дано:** WiFi подключён, NTP синхронизирован, хомяк бежит
**Действие:** колесо делает 5 оборотов за секунду
**Ожидаемо:** батч из 5 тиков отправлен, в БД 5 новых строк, буфер очищен

### E-02 — NTP не синхронизирован
**Дано:** ESP32 только что стартовал, NTP ещё не получен
**Действие:** хомяк сделал тик
**Ожидаемо:** тик попал в буфер, но не отправляется пока нет времени

### E-03 — Сервер недоступен (кратко)
**Дано:** сервер лежит 2 минуты
**Действие:** хомяк продолжает бежать
**Ожидаемо:** буфер накапливает тики, при восстановлении всё досылается одним или несколькими батчами

### E-04 — WiFi потерян и восстановлен
**Дано:** роутер перезагрузился (~2 мин)
**Действие:** хомяк бежит всё время
**Ожидаемо:** буфер держит тики, после реконнекта всё доходит до сервера

### E-05 — Переполнение буфера
**Дано:** сервер недоступен 110+ минут (больше ёмкости буфера)
**Действие:** хомяк продолжает бежать
**Ожидаемо:** старые тики вытесняются новыми (кольцевой буфер), данные частично теряются — это приемлемо

### E-06 — Дублированный батч
**Дано:** батч отправлен, ответ потерялся, ESP32 отправил повторно
**Действие:** сервер получает два одинаковых батча
**Ожидаемо:** второй INSERT игнорируется (ON CONFLICT DO NOTHING), в БД нет дублей

### E-07 — Неверный API key
**Дано:** ключ в ESP32 не совпадает с ключом на бэкенде
**Действие:** отправка батча
**Ожидаемо:** сервер вернул 401, ESP32 логирует ошибку

## Backend (FastAPI)

### B-01 — Валидный батч
**Запрос:** корректный JSON + верный X-API-Key
**Ожидаемо:** 200 OK, тики в БД

### B-02 — Пустой массив тиков
**Запрос:** `{"d": "hamster-wheel", "ticks": []}`
**Ожидаемо:** 200 OK, ничего в БД (или 400 — определить поведение)

### B-03 — Неверный API key
**Запрос:** X-API-Key: wrong
**Ожидаемо:** 401 Unauthorized

### B-04 — Битый JSON
**Запрос:** невалидный JSON
**Ожидаемо:** 422 Unprocessable Entity

### B-05 — Большой батч (буфер слился после долгого оффлайна)
**Запрос:** батч из 10 000 тиков
**Ожидаемо:** все тики записаны, ответ в разумное время (<5 сек)

### B-06 — Определение старта сессии
**Дано:** последний тик в БД был 5 минут назад
**Действие:** пришёл новый батч
**Ожидаемо:** бэкенд определил новую сессию и отправил Telegram уведомление

### B-07 — Старт сессии не срабатывает повторно
**Дано:** хомяк уже бежит, тики идут каждую секунду
**Действие:** очередной батч
**Ожидаемо:** Telegram уведомление не отправляется повторно

## База данных

### D-01 — Уникальный индекс
**Действие:** вставить два тика с одинаковым device_id + tick_ms
**Ожидаемо:** второй INSERT проигнорирован, в таблице одна строка

### D-02 — Вычисление сессий
**Дано:** набор тиков с двумя паузами > 60 сек
**Действие:** SQL запрос для вычисления сессий
**Ожидаемо:** 3 сессии определены корректно

### D-03 — Вычисление дистанции за день
**Дано:** 10 000 тиков за сутки
**Действие:** запрос дистанции
**Ожидаемо:** 10 000 × 0.6597 м = 6.597 км

## Frontend (Next.js)

### F-01 — Real-time скорость
**Дано:** пользователь на дашборде, хомяк начинает бежать
**Ожидаемо:** скорость появляется на экране в течение ~1 сек после первых тиков

### F-02 — Скорость обнуляется при остановке
**Дано:** хомяк остановился
**Ожидаемо:** скорость показывает 0 после N секунд без тиков

### F-03 — Статистика за день
**Ожидаемо:** дистанция, количество сессий, общее время бега за сегодня

### F-04 — Статистика за месяц
**Ожидаемо:** график активности по дням, суммарная дистанция

### F-05 — Страница открыта когда хомяк не бежит
**Ожидаемо:** последняя активность, статистика — без ошибок

### F-06 — Страница открыта впервые (нет данных)
**Ожидаемо:** пустое состояние без ошибок, понятный UI

## Telegram

### T-01 — Уведомление при старте бега
**Ожидаемо:** сообщение приходит в течение ~2 сек после первого тика новой сессии

### T-02 — Ссылка в уведомлении ведёт на фронтенд
**Ожидаемо:** URL открывается, показывает real-time дашборд

### T-03 — Уведомление не дублируется
**Ожидаемо:** за одну сессию — одно уведомление

## End-to-End

### EE-01 — Полный цикл бега
1. Хомяк начинает бежать
2. Telegram уведомление пришло
3. Открыл ссылку — вижу real-time скорость
4. Хомяк остановился — скорость = 0
5. Статистика за день обновилась

### EE-02 — Разрыв WiFi во время бега
1. Хомяк бежит, данные идут
2. WiFi отключился на 3 минуты
3. WiFi восстановился
4. Накопленные тики дошли до сервера
5. На графике нет пробела

### EE-03 — Перезагрузка ESP32
1. ESP32 перезагрузился (питание)
2. Подключился к WiFi, синхронизировал NTP
3. Хомяк побежал — данные идут корректно
4. Telegram уведомление пришло (новая сессия)
