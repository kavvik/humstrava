# Architecture

## Суть проекта

Система мониторинга хомячьего колеса. ESP32 с герконом фиксирует каждый оборот колеса (тик), передаёт сырые данные на бэкенд. Вся интерпретация — на бэкенде и фронтенде.

## Компоненты

```
ESP32 (геркон + WiFi)
  → POST /ticks
  → FastAPI (Railway)
  → Supabase (PostgreSQL + Realtime)
  → Next.js (Vercel) — дашборд, real-time
  → Telegram Bot — уведомления
```

## Стек

| Слой | Технология | Хостинг |
|---|---|---|
| Устройство | ESP32 + Arduino/MicroPython | физически дома |
| Backend API | FastAPI (Python) | Railway |
| База данных | PostgreSQL | Supabase |
| Real-time | Supabase Realtime (WebSocket) | Supabase |
| Frontend | Next.js | Vercel |
| Уведомления | Telegram Bot | Railway (тот же сервис) |

## Latency real-time

ESP32 батч раз в ~1 сек → FastAPI (~50ms) → Supabase insert → Realtime push (~100–200ms) → фронт.
Итого ~300–500ms. Для хомяка — незаметно.

## Принцип хранения данных

ESP32 шлёт только сырые тики (timestamp каждого оборота).
Сессии, дистанция, скорость — всё вычисляется из тиков на бэкенде/фронтенде.
Это даёт гибкость: можно менять определения без перезаписи исходных данных.

## Параметры колеса

- Диаметр: 21 см
- Длина окружности: ~65.97 см
- 1 тик = 1 оборот = ~0.66 м

## Сессии

Сессия не хранится как физическая сущность — вычисляется из сырых тиков.
Определение: gap между тиками > N секунд = граница сессии.
N задаётся параметром, можно менять ретроактивно.
